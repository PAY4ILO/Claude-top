# LWL — сайт minecraft-сервера

Лендинг, личный кабинет и собственный сервер сайта для Minecraft-сервера LWL.
Интерфейс — чистые HTML/CSS/JS без фреймворков и сборки, адаптив от 320px до широких мониторов.
Сервер — Node.js + SQLite **без единой зависимости** (только встроенные модули Node 22.13+).

Фирменный стиль (цвета, логотип, персонажи, шрифт заголовков Russo One) взят из макета Figma
[`YKqqIlIyP7Xq28pw7R1e5T`](https://www.figma.com/design/YKqqIlIyP7Xq28pw7R1e5T/Untitled?node-id=0-1),
а компоновка переработана — см. «Что изменено относительно макета».

| Часть | Что внутри |
| --- | --- |
| `index.html` | Лендинг: первый экран с призывом подать заявку, «О сервере», «Сейчас на сервере: N», несколько карточек игроков, «Как попасть на сервер», Telegram, футер |
| `players.html` | Публичная страница «Игроки»: карточки всех, кто играет (ник, скин, «о себе», соцсети), поиск |
| `lk.html` | Кабинет: заявка, поддержка, вкладка «Сервер» (адрес, сборки), «Игроки» со статистикой, профиль с «Моей карточкой» и своим скином; у админа — заявки, обращения, люди и роли, управление сервером и сборками |
| `server/` | Сервер сайта: API, база SQLite, раздача страниц |
| `deploy/` | Установка на Linux одной командой: служба с автозапуском, nginx, HTTPS, бэкапы — **[инструкция](deploy/README.md)** |
| `minecraft/` | Моды для сервера Fabric 26.3: скины, авторизация с вайтлистом и статистика игроков для сайта — [инструкция](minecraft/README.md) |

## Запуск у себя

```bash
LWL_ADMINS=you@example.com npm start     # http://localhost:8080
```

Зарегистрируйтесь с почтой из `LWL_ADMINS` — аккаунт сразу станет «Создателем» (админ со всеми правами). База и загруженные сборки
лежат в `./data/` (папка в `.gitignore`, в репозиторий не попадает). Нужен Node.js 22.13 или новее.
Все настройки — переменные окружения, см. `server/config.js` и `deploy/lwl.env.example`.

**На свою Linux-машину с доменом:** `sudo ./deploy/install.sh ваш-домен.ru ваша@почта.ru` —
подробно в [deploy/README.md](deploy/README.md), включая DNS на reg.ru, автозапуск и бэкапы.

## Роли

| Роль | Кто | Что видит |
| --- | --- | --- |
| **Гость** | без входа | лендинг и страницу «Игроки»: ник, скин, позу и фон, «о себе», соцсети каждого игрока |
| **Пользователь** | каждый после регистрации | заявку, поддержку, профиль, «Игроки» (как гость) |
| **Игрок** | заявку одобрили (или выдал админ) | + вкладку «Сервер»: адрес с кнопкой «Скопировать», как зайти (с лицензией или с паролем), сборки для Prism Launcher, CurseForge и Modrinth; «Игроки» со статистикой из игры и «в сети»; свою карточку и свой скин в профиле |
| **Админ** | выдаёт создатель (или админ с правом «Админы») | разделы по выданным правам: заявки, обращения, «Люди» (роли, ссылки сброса пароля), «Сервер» (адрес, подсказка, Telegram/Discord, сборки), удаление, назначение админов |
| **Создатель** | владельцы из `LWL_ADMINS` | всё; раздаёт права админам; его нельзя понизить, удалить или выдать на него ссылку сброса пароля |

Права админа (`server/lib/permissions.js`): «Заявки», «Обращения», «Люди», «Сервер» — выдаются по умолчанию,
«Удаление» и «Админы» — только если создатель отметит их в «Люди» → админ → «Права админа».

Роль видна под ником («префикс»). Когда роль или права меняют, открытый кабинет перестраивается сам —
перезагружать страницу не нужно.

| `#/admin/applications[/:id]` | Заявки: фильтры и поиск слева, анкета, решение, вайтлист (добавлен сам / «Повторить» / команда) и удаление справа |
| `#/admin/tickets[/:id]` | Обращения: список с непрочитанными и «в сети» слева, чат справа (закрыть, удалить) |
| `#/admin/users[/:id]` | Люди: роли, права админов (для создателя), запросы «Забыли пароль?», одноразовые ссылки сброса, удаление |
| `#/reset/:токен` | Новый пароль по ссылке от администратора (без входа) |

Что продумано:

- **Пустые состояния.** Нет заявки, нет обращений, пустой чат, «ничего не нашлось», «выберите обращение».
- **Загрузка.** Скелетоны, спиннеры на кнопках.
- **Ошибки.** Ошибки полей и общие, экран «Не удалось загрузить» с кнопкой «Повторить», истёкшая сессия, 404, «нет доступа».
- **Чат:**
  - сообщение появляется сразу, до ответа сервера; неотправленное можно повторить или удалить;
  - повторная отправка не создаёт дублей;
  - при прокрутке вверх подгружается история, есть разделители по дням;
  - сообщения группируются по автору;
  - кнопка «N новых сообщений», если вы прокрутили ленту вверх;
  - статус «в сети / был(а) N минут назад», галочки у своих сообщений (одна — доставлено, две — прочитано), бейджи непрочитанного в меню и в заголовке вкладки;
  - ссылки кликабельны, HTML из сообщений не выполняется;
  - черновик сохраняется, поле растёт по высоте, счётчик символов;
  - Enter отправляет сообщение, Shift+Enter переносит строку (на телефоне Enter переносит строку);
  - админ может закрыть обращение и открыть его снова, а с правом «Удаление» — удалить (вместе с фото и файлами);
  - фото и любые файлы — скрепкой, вставкой из буфера (Ctrl+V) или перетаскиванием в окно чата: сначала полоска выбранных
    с превью и «✕», текст из поля становится подписью к первому файлу; каждый файл уходит отдельным сообщением с прогрессом,
    не ушёл — «Повторить». В ленте фото — превью (место оставлено заранее, лента не прыгает), по клику — крупно;
    файл — карточка со значком, именем, размером и «Скачать». В списке обращений — «Фото» или имя файла.
- **Мобильная версия.** Нижние вкладки, чат на весь экран с кнопкой «назад», учёт безопасных зон экрана, окна открываются снизу, на лендинге меню-бургер.
- **Доступность.** Ловушка фокуса в окнах и меню, Esc, aria-атрибуты, видимый фокус, `prefers-reduced-motion`.

## Безопасность

- **Пароли** — scrypt (N=2¹⁵, соль на пароль), сравнение за постоянное время; по времени ответа не понять, есть ли аккаунт.
- **Сессия** — случайный токен в httpOnly-куке (`SameSite=Lax`, `Secure` на https); в базе хранится только его SHA-256. «Запомнить меня» — 30 дней, иначе до закрытия браузера. Смена пароля завершает остальные сессии.
- **CSRF** — изменяющие запросы требуют заголовок `X-Requested-With: lwl`, чужой `Origin` отклоняется.
- **Перебор** — 5 неверных паролей → блокировка на минуту; лимиты на регистрацию, запросы сброса, сообщения.
- **Сброс пароля** — сайт не шлёт писем: пользователь оставляет запрос, админ выдаёт одноразовую ссылку на сутки.
- **Файлы** — аватары проверяются по сигнатуре (JPEG/PNG/WebP), сборки — только `.zip`/`.mrpack` с настоящим zip-заголовком; наружу отдаются только страницы и `assets/`.
- **CSP** без `unsafe-inline`, `frame-ancestors 'none'`, `nosniff`; HTML из сообщений не выполняется.
- **Данных пользователей в репозитории нет**: база живёт в `LWL_DATA_DIR` на машине.

## API

Всё под `/api`, ответы — JSON, время — миллисекунды Unix. Ошибки: статус 4xx/5xx и тело
`{ "code": "…", "message": "текст для пользователя", "fields": { "поле": "ошибка" } }`
(коды `VALIDATION`, `INVALID_CREDENTIALS`, `NICK_TAKEN`, `EMAIL_TAKEN`, `UNAUTHORIZED`, `FORBIDDEN`,
`NOT_FOUND`, `CONFLICT`, `TOO_LARGE`, `RATE_LIMITED` + `Retry-After`). Изменяющие запросы — с заголовком
`X-Requested-With: lwl`. На странице всё это делает `assets/js/api.js` — **единственный** файл, который ходит в API.

Для WebSocket/SSE заменить нужно только `Api.chats.subscribe`.

### Заявка и сервер Minecraft

В анкете игрок обязательно указывает, есть ли у него лицензия (`license`). Когда админ одобряет заявку,
сайт сам добавляет ник в вайтлист мода LWL Auth (см. `minecraft/README.md`) через RCON сервера:

- есть лицензия → `wl add <ник>`: игрок заходит без пароля, лицензию проверяет Mojang;
- нет лицензии → `wl add <ник> cracked`: вход по паролю, даже если такой ник есть у чьей-то лицензии.

Результат виден в карточке заявки. Если сервер был выключен — там ошибка и кнопка «Повторить».
Если RCON не настроен (`LWL_RCON_PASSWORD` пустой), вместо этого показывается готовая команда
с кнопкой «Скопировать» — её вводят в консоль сервера вручную. Как включить — `deploy/README.md`, пункт 9.

### Карточки игроков

У каждого игрока на сайте есть карточка. Её видят все, даже без входа: на странице `players.html`
(«Игроки» в меню), несколько штук — на главной. Гость видит ник, скин в выбранной позе на выбранном фоне,
«о себе» (до 140 символов) и соцсети (Telegram, Discord, YouTube, Twitch, VK, TikTok — ссылки собирает сам
сайт из ника, так что подсунуть чужую ссылку нельзя). Тем, кто вошёл с ролью «Игрок» или «Админ», карточка
показывает больше: «в сети» или «был(а) N назад», наиграно часов, смерти, мобы, пройденное расстояние,
звания (Старожил — 100+ ч, Шахтёр — 10 000+ блоков, Путешественник, Охотник, Знаток) и вкладку «Топы».

**Откуда статистика.** Мод `lwl-stats` на Minecraft-сервере (`minecraft/README.md`) раз в минуту присылает,
кто в игре, а раз в 5 минут и при выходе игрока — его статистику из игры. Сайт считает игрока вышедшим через
150 с без вестей. Координаты, инвентарь, IP и способ входа мод не отправляет, сайт их не принимает.

**Скины.** Скин из игры сайт скачивает только с `https://textures.minecraft.net/texture/<hex>` и хранит у себя
(`LWL_DATA_DIR/skins/<sha256>.png`) — браузер посетителя к Mojang не ходит. В профиле игрок может загрузить
свой PNG: он сразу виден на сайте, а если настроен RCON и `LWL_PUBLIC_URL` — публичный адрес сайта, —
сайт выполняет на сервере `skin of <ник> url <адрес сайта>/api/skins/<хеш>.png [slim]` (мод `lwl-skins`
скачивает картинку через MineSkin, поэтому адрес должен открываться из интернета). Иначе кабинет честно
пишет, что скин на сервер поставит администрация. Показывается более новый из двух скинов: свой с сайта
или тот, что игрок потом поставил в игре, — так карточка сама следует за скином в Minecraft.
Кнопка «Как в игре» убирает свой скин с сайта.

**Скин по нику.** В кабинете можно вписать ник лицензии: сайт узнаёт скин у Mojang (`api.mojang.com`,
запасной — `api.minecraftservices.com`, профиль — `sessionserver.mojang.com`; ответы кешируются на 10 минут),
картинку всё так же качает только с `textures.minecraft.net`, а на сервер через RCON уходит
`skin of <ник> set <ник лицензии>` — мод сам спросит Mojang, публичный адрес сайта для этого не нужен.
Это единственные внешние адреса, к которым ходит сервер сайта, кроме `textures.minecraft.net`.

**Как стоит персонаж.** В «Моей карточке» поза настраивается отдельно для маленькой карточки и для окна,
которое открывается по нажатию: готовая поза или своя — ползунками для головы, тела, рук и ног, «Присесть»;
плюс размер фигуры (60–130 %) и поворот. В окне игрока посетитель может примерить другие позы, кнопка
«Как у игрока» возвращает настроенную.

**Свой фон.** Кроме готовых фонов игрок может загрузить свою картинку (JPEG, PNG, WebP). Браузер сам
уменьшает её до 1280 точек и сжимает в WebP — обычно выходит 100–300 КБ, сервер принимает не больше 400 КБ.
Хранится в `LWL_DATA_DIR/backgrounds/<sha256>.<webp|jpg|png>`, старая картинка удаляется при замене. Один фон —
и для карточки, и для окна игрока. Неподходящую картинку админ с правом «Люди» убирает кнопкой
«Убрать картинку фона» в окне игрока.

**Скин по умолчанию.** Если скина нет ни в игре, ни на сайте, на карточке — классический Стив (текстура
`31f477eb…` с textures.minecraft.net; сайт скачивает её один раз и хранит у себя).

**Приватность.** В «Моей карточке» игрок может скрыть всю карточку (её не увидит никто, в том числе
в «Топах»; в «Сейчас на сервере: N» игрок учитывается только числом, без ника) или отдельные поля: время в игре, смерти, мобов, убийства игроков, блоки,
расстояние, достижения, первый вход, «когда был в игре». Скрытое не уходит из API вовсе.

## Что изменено относительно макета

- **Текст.** Длинные тексты в макете набраны Russo One — это акцидентный шрифт, абзацы им читаются тяжело. Теперь Russo One остаётся для заголовков, кнопок и логотипа, а основной текст набран Inter.
- **Шапка лендинга.** Логотип с названием, меню «О сервере / Как попасть / Telegram» и две кнопки: «Войти» (после входа — «Личный кабинет») и главная — «Подать заявку».
- **Первый экран.** Раньше там была только картинка. Теперь есть заголовок «Здесь историю творите вы», короткое описание, кнопки действия и 3D-логотип.
- **«О нас»** → «О сервере»: вводный абзац и четыре широкие карточки с заголовками. Стороны чередуются, опечатки в текстах поправлены.
- **Персонажи выглядывают над карточками**, как в макете: стоят на нижнем крае карточки, голова торчит над верхним. Так сделано везде — на лендинге и в кабинете (карточка заявки, плитки поддержки и счётчиков, «Моя заявка», чат поддержки, экран входа). На телефоне персонаж по центру над карточкой.
- **Новые блоки.** «Как попасть на сервер» (три шага) объясняет, зачем регистрироваться. Баннер Telegram. Футер с навигацией и дисклеймером Mojang.
- **Кабинет стал приложением.** Слева меню разделов с бейджами, на телефоне — нижние вкладки. Профиль и «Выйти» — в меню под аватаром в шапке, а не огромными кнопками в углах экрана.
- **Главная игрока.** Большая карточка со статусом заявки и одной понятной кнопкой: «Подать заявку», «Подробнее» или «Подать заново». Ниже плитки «Тех поддержка» и «Профиль».
- **Главная админа.** Счётчики новых заявок и непрочитанных обращений, списки «Ждут решения» и «Последние обращения».
- **Заявки и обращения у админа** открываются рядом со списком (список | карточка или чат), без перехода между страницами.
- **Чат.** Аватар и статус собеседника в шапке, пузыри сообщений, компактное поле ввода с круглой кнопкой отправки. На телефоне чат открывается на весь экран.

  - шапка `#202020`;
  - полоса сверху `#005337`;
  - карточки `#343434`;
  - градиент кнопок `#1598D9 → #1EC5DC`;
  - «в сети» `#1F9837`.
- **Шрифт заголовков** — Russo One.
- **Картинки.** Оригиналы байт в байт как в Figma лежат в `design/figma/originals/`, рендеры фреймов макета — в `design/figma/frames/`. На сайте используются WebP-обрезки по кадрам слоёв (скрипт `tools/prepare-assets.py`).
- **Логотип и иконка Telegram в Figma — растровые PNG**, поэтому `logo.svg`, `logo-3d.svg` и `telegram.svg` получены векторизацией. Сходство с оригиналом проверено попиксельно: средняя разница около 2 из 255.
- **Шрифты** Russo One и Inter лежат в `assets/fonts` (лицензия OFL).

`tools/figma-export.mjs` — выгрузка тех же данных напрямую через REST API Figma (`FIGMA_TOKEN` со скоупом **File content: Read-only**).

Обратно, сайт → Figma: `npm run figma:cards` (`tools/figma-cards.mjs`) снимает карточки игроков, окно игрока и «Мою карточку»
с настоящей вёрстки в SVG со слоями — `design/figma/cards/` (как открыть и вернуть правки — в README там же).

## Тесты

```bash
npm install && npx playwright install chromium
npm run test:api   # API сервера без браузера: 39 сценариев
npm test           # сквозной сценарий в браузере против настоящего сервера: 112 проверок
```

Оба прогона поднимают сервер на временной базе и потом её удаляют. Браузерный сценарий — два человека
в разных браузерах: владелец-админ и новичок. Он проверяет:

- регистрацию, роли и меню;
- настройки сервера, создание, загрузку и публикацию сборки;
- заявку с выбором лицензии, одобрение → «Игрок» → вкладку «Сервер» и скачивание сборки;
- переписку в реальном времени;
- «Забыли пароль?» → ссылку от админа → новый пароль;
- карточки игроков: статистика от «мода» → «в сети», часы, км, звания, окно с 3D-скином; поза, фон, «о себе»,
  соцсети и свой скин в профиле; что видит гость (на 320px, без статистики); скрыть карточку → её нет в списках;
- смену ролей, закрытие обращения, экран без сети, выход;
- что в базе пароли только хешем.
