# Как запустить сайт LWL на своей Linux-машине

Сайт — это одна программа на Node.js (`server/`) и одна база SQLite (файл `/var/lib/lwl/lwl.db`).
Перед ней стоит nginx: он раздаёт сайт по HTTPS на вашем домене. Всё ставится одной командой,
а сайт сам запускается при включении машины и перезапускается, если упал.

## 1. Что нужно

- Машина с **Ubuntu 22.04/24.04** или **Debian 12** (VPS или домашний компьютер) и доступ по SSH с `sudo`.
- **Белый (публичный) IP.** На VPS он есть всегда. Дома — уточните у провайдера («белый/статический IP»)
  и пробросьте порты на роутере: **80** и **443** (сайт), **25565** (Minecraft) → на эту машину.
- **Домен** (например, на reg.ru).

## 2. Домен на reg.ru

1. Купите домен: reg.ru → «Домены».
2. Откройте «Мои домены» → ваш домен → «DNS-серверы и управление зоной». DNS-серверы оставьте
   от reg.ru (`ns1.reg.ru`, `ns2.reg.ru`).
3. В «Управлении зоной» добавьте записи:
   - **A**, имя `@`, значение — **внешний** IP машины;
   - **A**, имя `www`, значение — тот же IP.

   Внешний IP узнать на самой машине: `curl -4 ifconfig.me`. Адрес вида `192.168.…` сюда не подходит:
   он виден только внутри вашей домашней сети. Дома IP должен быть постоянным: если он меняется,
   запись устареет и сайт пропадёт.
4. Подождите: обычно 15–60 минут, иногда до суток. Проверка на машине: `getent hosts ваш-домен.ru` —
   должен показать ваш IP. Если не показывает ничего даже через несколько часов, проверьте в reg.ru,
   что домен **делегирован**: оплачен, нет невыполненных задач вроде «подтвердите данные администратора»,
   DNS-серверы указаны. Пока домен не делегирован, записи из «Управления зоной» никому не видны.

Хотите, чтобы игроки заходили по домену (например, `play.ваш-домен.ru`)? Добавьте ещё одну
**A**-запись с именем `play` на тот же IP (если Minecraft на этой же машине) и впишите этот адрес
в кабинете: «Сервер» → «Адрес сервера». Игроки адрес не видят: они заходят по личному коду,
а мод LWL получает адрес у сайта (пункт 9, «Вход по коду»).

## 3. Установка (5 минут)

```bash
sudo apt update && sudo apt install -y git
git clone https://github.com/pay4ilo/claude-top.git lwl
cd lwl
sudo ./deploy/install.sh ваш-домен.ru ваша@почта.ru
```

Если репозиторий приватный, `git clone` спросит логин и **токен** GitHub вместо пароля
(GitHub → Settings → Developer settings → Personal access tokens). Можно и просто скачать
архив кода с GitHub, распаковать на машине и запустить `install.sh` из этой папки.

Установщик:

- ставит Node.js 24, nginx и certbot;
- создаёт системного пользователя `lwl` и папки:
  - `/opt/lwl` — код,
  - `/var/lib/lwl` — база, сборки, фото и файлы из чата поддержки,
  - `/etc/lwl/lwl.env` — настройки,
  - `/var/backups/lwl` — бэкапы;
- включает службу **`lwl`**: автозапуск при загрузке и перезапуск через 3 секунды после падения;
- включает ежедневный бэкап базы и файлов из чата (04:30, хранится 14 дней);
- настраивает nginx и HTTPS-сертификат Let's Encrypt (продлевается сам).

Если на машине уже работают другие программы, установщик их не трогает. Другие сайты nginx
(в том числе `default`) остаются как есть. Если порт 8080 занят, сайт займёт следующий свободный
(записан в `LWL_PORT`).

**Если порты 80/443 уже занимает Caddy**, nginx и certbot не ставятся: сайт подключается к вашему Caddy.
Установщик кладёт блок сайта в `/etc/caddy/lwl.caddy` и дописывает в конец `/etc/caddy/Caddyfile`
строку `import /etc/caddy/lwl.caddy`. Копия Caddyfile до правки сохраняется рядом, в `Caddyfile.bak-ДАТА`.
Потом установщик выполняет `systemctl reload caddy`.
- Если Caddy слушает конкретный IP (`bind`), сайт слушает тот же.
- Сертификат Caddy получает и продлевает сам.
- Если Caddy не принял настройку, всё возвращается как было, и остальные сайты продолжают работать.
- Отключить сайт от Caddy: удалите строку `import /etc/caddy/lwl.caddy` и выполните `sudo systemctl reload caddy`.

**Caddy в Docker** (контейнер с `network_mode: host`, Caddyfile примонтирован с машины) установщик тоже подключит сам.
- По настройкам контейнера он находит, где на машине лежит Caddyfile.
- Дописывает в его конец блок сайта между строками `# >>> Сайт LWL` и `# <<< Сайт LWL`.
- Выполняет `docker exec <контейнер> caddy reload`.
- Файл меняется на месте, поэтому примонтированный файл не отваливается.
- Копия до правки сохраняется рядом (`Caddyfile.bak-ДАТА`). При ошибке файл возвращается как был.
- Отключить сайт: удалите эти строки вместе с тем, что между ними, и выполните
  `docker exec <контейнер> caddy reload --config /etc/caddy/Caddyfile --adapter caddyfile`.

В остальных случаях (Caddy запущен вручную, в Docker без host-сети и т. п.) установщик ничего в Caddy
не меняет. Он печатает блок, который нужно добавить в ваш Caddyfile вручную; этот блок сохраняется в `/etc/lwl/lwl.caddy`.

Если порты 80/443 держит какая-то другая программа (не nginx и не Caddy), установщик остановится
и покажет, какая именно.

Если на момент установки DNS ещё не обновился, сертификат не выдастся — установщик так и скажет.
Когда `getent hosts ваш-домен.ru` покажет ваш IP, выполните:
`sudo certbot --nginx -d ваш-домен.ru -d www.ваш-домен.ru --redirect`.
С Caddy ничего запускать не нужно: он сам повторяет попытки. Если сертификата нет через полчаса
после того, как домен заработал, перезагрузите Caddy. Для службы: `sudo systemctl reload caddy`,
посмотреть, что происходит: `journalctl -u caddy --since "1 hour ago" | grep ваш-домен`.
Для Docker: `sudo docker exec caddy caddy reload --config /etc/caddy/Caddyfile --adapter caddyfile`,
а посмотреть: `sudo docker logs --since 1h caddy 2>&1 | grep ваш-домен`.

Пока нет сертификата, войти на сайт не получится: кука входа передаётся только по HTTPS.

## 4. Стать админом

Почта, которую вы указали при установке, записана в `LWL_ADMINS` в `/etc/lwl/lwl.env`.
Откройте сайт и **зарегистрируйтесь с этой почтой** — аккаунт сразу станет «Создателем» (под ником).
Это админ со всеми правами: его нельзя понизить или удалить из админки, и только он раздаёт права
другим админам («Люди» → админ → «Права админа»).

Дальше всё настраивается в кабинете:

- **«Сервер»** — адрес сервера (его видит только мод, игроки — нет), версия, подсказка для игроков, ссылки на Telegram и Discord, сборки
  (кнопка «Добавить сборку», потом «Загрузить файл», потом «Опубликовать»);
- **«Люди»** — роли, права админов и ссылки для сброса пароля;
- **«Заявки»** — при одобрении человек становится «Игроком», у него открывается вкладка «Сервер»,
  а если настроен RCON (пункт 9) — ник сразу попадает в вайтлист сервера.

## 5. Как это работает после установки

| Что | Команда |
|-----|---------|
| Состояние сайта | `systemctl status lwl` |
| Логи в реальном времени | `journalctl -u lwl -f` |
| Перезапустить | `sudo systemctl restart lwl` |
| Список аккаунтов | `sudo lwl-cli users` |
| Сделать админом | `sudo lwl-cli role НИК admin` |
| Ссылка для сброса пароля | `sudo lwl-cli reset-link НИК` |
| Бэкап вручную | `sudo systemctl start lwl-backup` (файл появится в `/var/backups/lwl`) |

Проверка автозапуска: `sudo reboot`, через минуту сайт снова открывается.

## 6. Обновление сайта

```bash
cd ~/lwl
git pull
sudo ./deploy/update.sh
```

Перед обновлением делается бэкап базы. Если в новой версии менялась база, она обновится сама при запуске.

## 7. Восстановление из бэкапа

```bash
sudo systemctl stop lwl
sudo cp /var/backups/lwl/lwl-2026-09-30.db /var/lib/lwl/lwl.db
sudo rm -f /var/lib/lwl/lwl.db-wal /var/lib/lwl/lwl.db-shm
# фото и файлы из чата — за тот же день, что и база
sudo rsync -a --delete /var/backups/lwl/attachments-2026-09-30/ /var/lib/lwl/attachments/
sudo chown -R lwl:lwl /var/lib/lwl/lwl.db /var/lib/lwl/attachments
sudo systemctl start lwl
```

Бэкап — это база (аккаунты, заявки, переписка, настройки и аватары) и папка `attachments-ДАТА` с фото и файлами
из чата поддержки. Файлы в чате не меняются, поэтому одинаковые файлы в снимках за разные дни — жёсткие ссылки
на одно и то же: лишнего места не занимают. Файлы сборок лежат в `/var/lib/lwl/packs/` и в бэкап не входят:
если нужно, копируйте их отдельно или просто загрузите заново.
Для надёжности время от времени скачивайте `/var/backups/lwl` на другой компьютер (`rsync -aH`, чтобы жёсткие
ссылки не превратились в копии).

## 8. Настройки (`/etc/lwl/lwl.env`)

| Переменная | Что это |
|------------|---------|
| `LWL_PUBLIC_URL` | Адрес сайта с `https://` — из него собираются ссылки сброса пароля |
| `LWL_ADMINS` | Почты или ники владельцев через запятую — всегда админы |
| `LWL_DATA_DIR` | Папка с базой, сборками и файлами из чата (`/var/lib/lwl`) |
| `LWL_PORT`, `LWL_HOST` | Где сайт слушает (`127.0.0.1:8080` или следующий свободный порт — выбирает установщик; наружу его отдаёт nginx). Меняете порт — поменяйте его и в `/etc/nginx/sites-available/lwl` |
| `LWL_TRUST_PROXY` | `1` — брать IP посетителя из заголовка nginx (для защиты от перебора паролей) |
| `LWL_MAX_UPLOAD_MB` | Максимальный размер сборки (по умолчанию 2048 МБ; в nginx стоит лимит 2100 МБ) |
| `LWL_CHAT_MAX_FILE_MB` | Максимальный размер одного фото или файла в чате поддержки (по умолчанию 25 МБ). Больше 2100 — поднимите и `client_max_body_size` в nginx |
| `LWL_RCON_PASSWORD` | Пароль RCON Minecraft-сервера — тогда сайт сам добавляет одобренных игроков в вайтлист (пункт 9). Пусто — выключено |
| `LWL_RCON_HOST`, `LWL_RCON_PORT` | Где RCON (по умолчанию `127.0.0.1:25575` — сервер на этой же машине) |
| `LWL_GAME_TOKEN` | Токен Minecraft-сервера для входа по коду (пункт 9). Создаётся сам при установке и обновлении; тот же — в `config/lwl/connect.json` сервера (`siteToken`). Пусто — сервер не может проверять коды |

После правки: `sudo systemctl restart lwl`.

## 9. Minecraft-сервер на этой же машине (необязательно)

Чтобы сервер тоже поднимался сам после перезагрузки, возьмите шаблон `deploy/minecraft.service.example`:
поправьте в нём папку, имя jar-файла и память и следуйте инструкции в начале файла. Не забудьте порт
25565 (`sudo ufw allow 25565/tcp`, если включён ufw, и проброс на роутере, если машина дома).
Моды для сервера и команда вайтлиста — в `minecraft/README.md`.

### Автодобавление в вайтлист (RCON)

Чтобы при одобрении заявки сайт сам выполнял на сервере `wl add <ник>` (или `wl add <ник> cracked`
для игроков без лицензии):

1. В `server.properties` Minecraft-сервера:
   ```
   enable-rcon=true
   rcon.port=25575
   rcon.password=длинный-случайный-пароль
   ```
   Пароль можно сгенерировать: `openssl rand -hex 16`. Перезапустите сервер.
2. На машине с сайтом допишите в `/etc/lwl/lwl.env` строку с тем же паролем и перезапустите сайт:
   ```bash
   echo 'LWL_RCON_PASSWORD=тот-же-пароль' | sudo tee -a /etc/lwl/lwl.env
   sudo systemctl restart lwl
   ```
   Если Minecraft на другой машине — ещё `LWL_RCON_HOST=её-IP` (и `LWL_RCON_PORT`, если порт не 25575).
3. В кабинете: «Сервер» → «Автодобавление в вайтлист» → «Проверить связь». Должен прийти список `/wl list`.

**Порт 25575 наружу не открывайте** (ни на роутере, ни в файрволе): RCON — это полный доступ к консоли
сервера. Он нужен только сайту, а сайт стоит рядом.

### Вход по коду (мод LWL)

Игроки не видят адрес сервера. У каждого во вкладке «Сервер» — личный код (`XXXX-XXXX-XXXX`, показывается
один раз). В игре: «Сетевая игра» → «Сервер LWL» → код. Мод спрашивает у сайта адрес по коду и подключается,
а сервер при входе проверяет код у сайта и без верного кода не пускает.

1. В кабинете: «Сервер» → «Адрес сервера» (например, `play.ваш-домен.ru` или `IP:порт`). Его получает только мод.
2. Токен сервера `LWL_GAME_TOKEN` установщик уже записал в `/etc/lwl/lwl.env` (и напечатал в конце установки).
   Посмотреть: `sudo grep LWL_GAME_TOKEN /etc/lwl/lwl.env`.
3. На Minecraft-сервере в `config/lwl/connect.json` впишите этот токен и адрес сайта, потом перезапустите сервер:
   ```json
   { "siteUrl": "http://127.0.0.1:8080", "siteToken": "токен из lwl.env" }
   ```
   `siteUrl` — `http://127.0.0.1:<LWL_PORT>`, если Minecraft на этой же машине, иначе `https://ваш-домен.ru`.

Код игрок создаёт сам («Получить код», «Новый код» — старый сразу перестаёт работать). Отозвать чужой код:
«Люди» → игрок → «Отозвать код входа»; на сервере — `/lwl code revoke НИК`. Сменить токен: поменяйте
`LWL_GAME_TOKEN` и `siteToken` на одно и то же и перезапустите сайт и сервер.

Это защита от случайной утечки адреса и вход только своих, а не анонимность: во время игры адрес сервера
всё равно можно увидеть средствами системы.

## 10. Если что-то не так

- **502 Bad Gateway** — сайт не запущен: `systemctl status lwl`, `journalctl -u lwl -n 50`.
- **Сайт открывается только по http** — не выдан сертификат (см. пункт 3).
- **Сайт за Caddy не открывается** — логи Caddy: `journalctl -u caddy -n 50` (служба) или
  `sudo docker logs --tail 50 caddy` (Docker); проверьте, что блок сайта есть в Caddyfile.
- **certbot: `DNS problem: NXDOMAIN`** — интернет пока не знает ваш домен: не добавлены A-записи или домен
  ещё не делегирован (см. пункт 2). Сайт и сертификат тут ни при чём, подождите и повторите.
- **certbot: `Timeout during connect` / `Connection refused`** — домен уже указывает на ваш IP, но порт 80
  снаружи закрыт: проброс портов 80 и 443 на роутере, файрвол, «белый» IP у провайдера.
- **Не загружается большая сборка** — проверьте `LWL_MAX_UPLOAD_MB` и свободное место (`df -h /var/lib/lwl`).
- **Не отправляется фото или файл в чате** — кабинет сам скажет, если файл больше `LWL_CHAT_MAX_FILE_MB`.
  Ошибка 413 от nginx — `client_max_body_size` меньше этого лимита; «Слишком много файлов подряд» — не больше
  30 файлов в минуту на человека. Место на диске: `du -sh /var/lib/lwl/attachments`.
- **У всех одинаковый IP в логах / блокировки срабатывают на всех сразу** — в `lwl.env` должно быть `LWL_TRUST_PROXY=1`.
- **Забыли пароль админа** — `sudo lwl-cli reset-link ВАШ_НИК` и откройте выданную ссылку.
- **Не добавляет в вайтлист** — «Сервер» → «Проверить связь» покажет причину: сервер выключен или RCON
  не включён, не тот пароль (`rcon.password` и `LWL_RCON_PASSWORD` должны совпадать), нет мода LWL Auth.
- **Сервер не пускает по коду, «Сайт недоступен»** — `siteToken` в `config/lwl/connect.json` не совпадает с
  `LWL_GAME_TOKEN` (в логе сервера будет 401) или неверный `siteUrl`. **Мод в игре пишет про ошибку 503** — в кабинете
  не указан «Адрес сервера».
